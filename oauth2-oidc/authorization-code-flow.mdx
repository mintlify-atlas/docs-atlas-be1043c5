The authorization code flow is the most widely used OAuth2 flow for applications that need to act on behalf of a user. The user authenticates with Ory, grants consent, and your application receives an authorization code that it exchanges for an access token. For public clients — single-page apps, mobile apps, and native apps — you must extend this flow with PKCE (Proof Key for Code Exchange) to prevent authorization code interception attacks.

## How the flow works

At a high level, the authorization code flow has four steps:

1. Your application redirects the user to Ory's authorization endpoint.
2. The user authenticates and grants consent.
3. Ory redirects the user back to your application with an authorization code.
4. Your application exchanges the code for an access token (and optionally an ID token and refresh token).

## Step-by-step walkthrough

<Steps>
  <Step title="Redirect the user to the authorization endpoint">
    Send the user to Ory's `/oauth2/auth` endpoint with the required parameters. Replace `$PROJECT_SLUG` with your Ory Network project slug.

    ```text
    https://$PROJECT_SLUG.projects.oryapis.com/oauth2/auth
      ?response_type=code
      &client_id=YOUR_CLIENT_ID
      &redirect_uri=https://yourapp.com/callback
      &scope=openid%20offline_access
      &state=RANDOM_STATE_VALUE
    ```

    Required parameters:

    | Parameter | Description |
    |---|---|
    | `response_type` | Must be `code` for the authorization code flow. |
    | `client_id` | The ID of your registered OAuth2 client. |
    | `redirect_uri` | Where Ory redirects the user after consent. Must be pre-registered on your client. |
    | `state` | A random value you generate to prevent CSRF attacks. Verify it matches when the callback arrives. |

    Optional parameters:

    | Parameter | Description |
    |---|---|
    | `scope` | Space-separated list of scopes. Include `openid` for an ID token, `offline_access` for a refresh token. |
    | `prompt` | `login` forces re-authentication, `consent` re-prompts for consent, `none` returns an error if interaction is needed. |
    | `max_age` | Maximum elapsed seconds since the user last authenticated before re-authentication is required. |
    | `id_token_hint` | A previously issued ID token, used to hint the current user's identity. |

  </Step>
  <Step title="User authenticates and grants consent">
    Ory presents the login and consent UI to the user. The user authenticates and reviews the requested scopes. If they approve, Ory generates an authorization code.
  </Step>
  <Step title="Receive the authorization code">
    Ory redirects the user to your `redirect_uri` with the authorization code and the `state` value you sent:

    ```text
    https://yourapp.com/callback?code=AUTHORIZATION_CODE&state=RANDOM_STATE_VALUE
    ```

    Before proceeding, verify that the `state` value matches what you generated in step 1.
  </Step>
  <Step title="Exchange the code for tokens">
    Make a POST request from your server (or client, for PKCE flows) to the token endpoint:

    ```bash
    curl -X POST https://$PROJECT_SLUG.projects.oryapis.com/oauth2/token \
      -H "Content-Type: application/x-www-form-urlencoded" \
      -d "grant_type=authorization_code" \
      -d "client_id=YOUR_CLIENT_ID" \
      -d "client_secret=YOUR_CLIENT_SECRET" \
      -d "code=AUTHORIZATION_CODE" \
      -d "redirect_uri=https://yourapp.com/callback"
    ```

    Ory responds with:

    ```json
    {
      "access_token": "ory_at_...",
      "token_type": "Bearer",
      "expires_in": 3600,
      "id_token": "eyJhbGciOiJSUzI1NiIsInR5...",
      "refresh_token": "ory_rt_..."
    }
    ```

    <Note>
    `id_token` is only returned if you included the `openid` scope. `refresh_token` is only returned if you included the `offline_access` scope and the client has the `refresh_token` grant type enabled.
    </Note>
  </Step>
</Steps>

## Add PKCE for public clients

PKCE is required for SPAs, mobile apps, and any client that cannot keep a `client_secret` confidential. PKCE replaces the client secret with a cryptographic challenge generated fresh for each authorization request.

<Steps>
  <Step title="Generate a code verifier and code challenge">
    Before the authorization redirect, generate a random `code_verifier` and derive a `code_challenge` from it using SHA-256:

    ```javascript
    async function generatePKCE() {
      // Generate a random 64-byte code verifier
      const array = new Uint8Array(64)
      crypto.getRandomValues(array)
      const codeVerifier = btoa(String.fromCharCode(...array))
        .replace(/=/g, "")
        .replace(/\+/g, "-")
        .replace(/\//g, "_")

      // Derive the code challenge via SHA-256
      const digest = await crypto.subtle.digest(
        "SHA-256",
        new TextEncoder().encode(codeVerifier)
      )
      const codeChallenge = btoa(String.fromCharCode(...new Uint8Array(digest)))
        .replace(/=/g, "")
        .replace(/\+/g, "-")
        .replace(/\//g, "_")

      return { codeVerifier, codeChallenge }
    }
    ```

    Store the `codeVerifier` securely (for example, in `sessionStorage`) — you'll need it in the token exchange step.
  </Step>
  <Step title="Include the code challenge in the authorization request">
    Append `code_challenge` and `code_challenge_method` to the authorization URL:

    ```javascript
    const { codeVerifier, codeChallenge } = await generatePKCE()
    const clientId = "YOUR_CLIENT_ID"
    const redirectUri = "https://yourapp.com/callback"

    const authorizationUrl =
      `https://$PROJECT_SLUG.projects.oryapis.com/oauth2/auth` +
      `?response_type=code` +
      `&client_id=${clientId}` +
      `&redirect_uri=${encodeURIComponent(redirectUri)}` +
      `&scope=openid` +
      `&state=RANDOM_STATE_VALUE` +
      `&code_challenge=${codeChallenge}` +
      `&code_challenge_method=S256`

    window.location.href = authorizationUrl
    ```
  </Step>
  <Step title="Exchange the code using the code verifier">
    Include the `code_verifier` instead of `client_secret` in the token request:

    ```javascript
    const code = new URLSearchParams(window.location.search).get("code")
    const codeVerifier = sessionStorage.getItem("pkce_code_verifier")

    const response = await fetch(
      "https://$PROJECT_SLUG.projects.oryapis.com/oauth2/token",
      {
        method: "POST",
        headers: { "Content-Type": "application/x-www-form-urlencoded" },
        body: new URLSearchParams({
          grant_type: "authorization_code",
          client_id: clientId,
          redirect_uri: redirectUri,
          code_verifier: codeVerifier,
          code: code,
        }).toString(),
      }
    )

    const tokens = await response.json()
    ```
  </Step>
</Steps>

<Warning>
Always use `S256` as the `code_challenge_method`. The `plain` method offers no security benefit over sending the verifier directly and should not be used in production.
</Warning>

## Client examples

<Tabs>
  <Tab title="SPA (public client)">
    Single-page apps use a public client with no client secret. Use PKCE on every request.

    **Create the client:**

    ```bash
    ory create oauth2-client \
      --token-endpoint-auth-method none \
      --grant-type authorization_code \
      --response-type code \
      --redirect-uri https://yourapp.com/callback \
      --scope openid
    ```

    **Authorization URL:**

    ```text
    https://$PROJECT_SLUG.projects.oryapis.com/oauth2/auth
      ?response_type=code
      &client_id=YOUR_CLIENT_ID
      &redirect_uri=https://yourapp.com/callback
      &scope=openid
      &state=RANDOM_VALUE
      &code_challenge=CODE_CHALLENGE
      &code_challenge_method=S256
    ```
  </Tab>
  <Tab title="Mobile/native app (public client)">
    Native apps use custom URI schemes to receive the authorization code. PKCE is required.

    **Create the client:**

    ```bash
    ory create oauth2-client \
      --token-endpoint-auth-method none \
      --grant-type authorization_code \
      --response-type code \
      --redirect-uri myapp://callback \
      --scope openid
    ```

    **Authorization URL:**

    ```text
    https://$PROJECT_SLUG.projects.oryapis.com/oauth2/auth
      ?response_type=code
      &client_id=YOUR_CLIENT_ID
      &redirect_uri=myapp://callback
      &scope=openid
      &state=RANDOM_VALUE
      &code_challenge=CODE_CHALLENGE
      &code_challenge_method=S256
    ```
  </Tab>
  <Tab title="Web server app (confidential client)">
    Server-side apps can store a client secret and authenticate with it. PKCE is still recommended.

    **Create the client:**

    ```bash
    ory create oauth2-client \
      --token-endpoint-auth-method client_secret_post \
      --grant-type authorization_code,refresh_token \
      --response-type code \
      --redirect-uri https://yourapp.com/callback \
      --scope openid,offline_access
    ```

    **Token exchange:**

    ```bash
    curl -X POST https://$PROJECT_SLUG.projects.oryapis.com/oauth2/token \
      -H "Content-Type: application/x-www-form-urlencoded" \
      -d "grant_type=authorization_code" \
      -d "client_id=YOUR_CLIENT_ID" \
      -d "client_secret=YOUR_CLIENT_SECRET" \
      -d "code=AUTHORIZATION_CODE" \
      -d "redirect_uri=https://yourapp.com/callback"
    ```
  </Tab>
</Tabs>

## Use refresh tokens

When the access token expires, you can get a new one without sending the user through the authorization flow again, as long as you have a refresh token.

To receive a refresh token:
1. Include `offline_access` in the `scope` parameter of your authorization request.
2. Ensure your OAuth2 client has the `refresh_token` and `authorization_code` grant types enabled.
3. The user must approve the `offline_access` scope on the consent screen.

**Refresh an access token:**

```javascript
const response = await fetch(
  "https://$PROJECT_SLUG.projects.oryapis.com/oauth2/token",
  {
    method: "POST",
    headers: { "Content-Type": "application/x-www-form-urlencoded" },
    body: new URLSearchParams({
      grant_type: "refresh_token",
      refresh_token: storedRefreshToken,
      client_id: "YOUR_CLIENT_ID",
      client_secret: "YOUR_CLIENT_SECRET", // omit for public clients
    }).toString(),
  }
)

const { access_token, refresh_token, id_token } = await response.json()
// Store the new refresh_token — the old one is now invalid
```

<Warning>
Refresh tokens are single-use. Every time you use a refresh token, Ory issues a new one and invalidates the previous one. Store the new refresh token immediately or you will lose access.
</Warning>

## Validate the ID token

If you requested the `openid` scope, the token response includes an ID token. Validate it by verifying its signature against Ory's public keys:

```javascript
import { createRemoteJWKSet, jwtVerify } from "jose"

const JWKS = createRemoteJWKSet(
  new URL(`https://$PROJECT_SLUG.projects.oryapis.com/.well-known/jwks.json`)
)

const { payload } = await jwtVerify(idToken, JWKS, {
  issuer: `https://$PROJECT_SLUG.projects.oryapis.com`,
  audience: "YOUR_CLIENT_ID",
})

console.log("User ID:", payload.sub)
console.log("Email:", payload.email)
```

<Tip>
Use a well-tested OAuth2/OIDC library such as [openid-client](https://github.com/panva/node-openid-client) for Node.js, [AppAuth](https://appauth.io/) for mobile, or [oidc-client-ts](https://github.com/authts/oidc-client-ts) for browsers. These handle PKCE, state validation, and token validation automatically.
</Tip>
