The client credentials grant is the OAuth2 flow for machine-to-machine (M2M) authentication. There is no user involved: a service identifies itself directly to Ory using its `client_id` and credentials, and receives an access token it can use to call protected APIs. Use this flow for microservices, background workers, scheduled jobs, and any server-side process that needs to authenticate itself rather than act on behalf of a user.

## How the flow works

The client credentials flow is a single round-trip between your service and Ory:

1. Your service sends its credentials and a `grant_type=client_credentials` request to the token endpoint.
2. Ory validates the credentials and returns an access token.
3. Your service presents the access token as a `Bearer` token to protected APIs.

There is no authorization endpoint redirect, no user session, and no refresh token.

## Authentication methods

Ory supports three ways for a client to authenticate itself at the token endpoint.

### Basic authentication

The client sends its `client_id` and `client_secret` base64-encoded in the `Authorization` header. This is the most common method for server-side clients.

**Create a client:**

```bash
ory create oauth2-client --project "$PROJECT_ID" \
  --name "My Service" \
  --grant-type client_credentials \
  --token-endpoint-auth-method client_secret_basic
```

**Request a token:**

```bash
curl -X POST https://$PROJECT_SLUG.projects.oryapis.com/oauth2/token \
  -H "Authorization: Basic $(echo -n 'CLIENT_ID:CLIENT_SECRET' | base64)" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials&scope=read"
```

```javascript
const clientId = "the-client-id"
const clientSecret = "the-client-secret"
const credentials = btoa(`${encodeURIComponent(clientId)}:${encodeURIComponent(clientSecret)}`)

const response = await fetch(
  "https://$PROJECT_SLUG.projects.oryapis.com/oauth2/token",
  {
    method: "POST",
    headers: {
      Authorization: `Basic ${credentials}`,
      "Content-Type": "application/x-www-form-urlencoded",
    },
    body: "grant_type=client_credentials&scope=read",
  }
)

const { access_token } = await response.json()
```

### Body (POST) authentication

The client includes its `client_id` and `client_secret` in the request body. Use this method when your HTTP client does not support custom `Authorization` headers.

**Create a client:**

```bash
ory create oauth2-client --project "$PROJECT_ID" \
  --name "My Service" \
  --grant-type client_credentials \
  --token-endpoint-auth-method client_secret_post
```

**Request a token:**

```bash
curl -X POST https://$PROJECT_SLUG.projects.oryapis.com/oauth2/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials" \
  -d "client_id=CLIENT_ID" \
  -d "client_secret=CLIENT_SECRET" \
  -d "scope=read"
```

```javascript
const params = new URLSearchParams({
  grant_type: "client_credentials",
  client_id: "the-client-id",
  client_secret: "the-client-secret",
  scope: "read",
})

const response = await fetch(
  "https://$PROJECT_SLUG.projects.oryapis.com/oauth2/token",
  {
    method: "POST",
    headers: { "Content-Type": "application/x-www-form-urlencoded" },
    body: params.toString(),
  }
)

const { access_token } = await response.json()
```

### Private key JWT

The client authenticates by signing a JWT with its own private key instead of sharing a secret. This is the most secure method because the private key never leaves the client.

**Create a client:**

```bash
ory create oauth2-client --project "$PROJECT_ID" \
  --name "My Service" \
  --grant-type client_credentials \
  --token-endpoint-auth-method private_key_jwt \
  --jwks-uri https://your-service.example.com/.well-known/jwks.json
```

<Note>
You can also provide the JSON Web Key Set inline (key: `jwks`) when creating the client via the HTTP API. This is not available through the Ory CLI.
</Note>

The JWT you sign must contain these claims:

| Claim | Required | Description |
|---|---|---|
| `iss` | Yes | Must be the `client_id` of the OAuth2 client. |
| `sub` | Yes | Must be the `client_id` of the OAuth2 client. |
| `aud` | Yes | The token endpoint URL: `https://$PROJECT_SLUG.projects.oryapis.com/oauth2/token` |
| `jti` | Yes | A unique identifier for this assertion. JTIs may only be used once. |
| `exp` | Yes | Expiration time. Keep the lifetime short (a few minutes). |
| `iat` | No | Issued-at time. |

**Request a token:**

```javascript
import { SignJWT, importPKCS8 } from "jose"
import { randomUUID } from "crypto"

const clientId = "the-client-id"
const tokenEndpoint = "https://$PROJECT_SLUG.projects.oryapis.com/oauth2/token"

const privateKey = await importPKCS8(process.env.PRIVATE_KEY_PEM, "RS256")

const clientAssertion = await new SignJWT({})
  .setProtectedHeader({ alg: "RS256" })
  .setIssuer(clientId)
  .setSubject(clientId)
  .setAudience(tokenEndpoint)
  .setJti(randomUUID())
  .setIssuedAt()
  .setExpirationTime("5m")
  .sign(privateKey)

const params = new URLSearchParams({
  grant_type: "client_credentials",
  client_id: clientId,
  client_assertion_type: "urn:ietf:params:oauth:client-assertion-type:jwt-bearer",
  client_assertion: clientAssertion,
  scope: "read",
})

const response = await fetch(tokenEndpoint, {
  method: "POST",
  headers: { "Content-Type": "application/x-www-form-urlencoded" },
  body: params.toString(),
})

const { access_token } = await response.json()
```

## Token response

Regardless of authentication method, a successful token request returns:

```json
{
  "access_token": "ory_at_JGhESDjKfHMQ8Wcy0cC3...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "read"
}
```

<Note>
The client credentials grant does not return a refresh token. When the access token expires, request a new one by repeating the token request with your client credentials.
</Note>

## Use the access token

Include the access token in the `Authorization` header of requests to your protected APIs:

```bash
curl https://your-api.example.com/resource \
  -H "Authorization: Bearer ory_at_JGhESDjKfHMQ8Wcy0cC3..."
```

```javascript
const response = await fetch("https://your-api.example.com/resource", {
  headers: {
    Authorization: `Bearer ${access_token}`,
  },
})
```

Your API validates the token by calling Ory's introspection endpoint or verifying the JWT signature locally (if JWT access tokens are enabled). See [Tokens and scopes](/oauth2-oidc/tokens-and-scopes) for details on token validation.

## Scope the token

Scopes in the client credentials flow define what the service is authorized to do. Specify the scopes your client needs at token request time using the `scope` parameter:

```bash
curl -X POST https://$PROJECT_SLUG.projects.oryapis.com/oauth2/token \
  -H "Authorization: Basic BASE64_CREDENTIALS" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials&scope=read write"
```

<Tip>
Request only the scopes your service needs for a given operation. This principle of least privilege limits the impact of a compromised token.
</Tip>

## Token caching

Client credentials tokens are safe to cache for their full lifetime (`expires_in` seconds). Requesting a new token on every API call adds unnecessary latency.

```javascript
let cachedToken = null
let tokenExpiry = 0

async function getAccessToken() {
  if (cachedToken && Date.now() < tokenExpiry - 30_000) {
    return cachedToken
  }

  const response = await fetch(
    "https://$PROJECT_SLUG.projects.oryapis.com/oauth2/token",
    {
      method: "POST",
      headers: {
        Authorization: `Basic ${credentials}`,
        "Content-Type": "application/x-www-form-urlencoded",
      },
      body: "grant_type=client_credentials&scope=read",
    }
  )

  const data = await response.json()
  cachedToken = data.access_token
  tokenExpiry = Date.now() + data.expires_in * 1000

  return cachedToken
}
```
