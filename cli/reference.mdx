This page provides a complete reference for every top-level command group in the Ory CLI. Each group lists its subcommands and the key flags available. For installation and authentication, see the [CLI installation guide](/cli/installation). For workflow examples, see [CLI basics](/cli/basics).

Run `ory help` at any time to see the top-level command list, or append `--help` to any command for context-specific usage information.

## Global flags

These flags are available on every command:

| Flag | Short | Description |
|------|-------|-------------|
| `--config` | `-c` | Path to the Ory Network configuration file |
| `--format` | | Output format: `default`, `json`, `json-pretty`, `yaml`, `jsonpath`, `jsonpointer` |
| `--help` | `-h` | Show help for the command |
| `--project` | | Project to use, either by ID or partial slug |
| `--quiet` | `-q` | Suppress output |
| `--workspace` | | Workspace to use, either by ID or partial name |
| `--yes` | `-y` | Confirm all prompts without interactive input |

## ory auth

Create a new Ory Network account or sign in to an existing account.

```bash
ory auth [flags]
ory auth [command]
```

| Subcommand | Description |
|-----------|-------------|
| `ory auth logout` | Remove the stored session from this machine |

**Key flags**

| Flag | Description |
|------|-------------|
| `--format` | Output format |

## ory create

Create Ory Network resources.

```bash
ory create [command]
```

| Subcommand | Description |
|-----------|-------------|
| `ory create event-stream` | Create a new event stream |
| `ory create jwk` | Create a JSON Web Key Set |
| `ory create oauth2-client` | Create an OAuth 2.0 client |
| `ory create organization` | Create a new B2B SSO organization |
| `ory create project` | Create a new Ory Network project |
| `ory create relationships` | Create relationship tuples from arguments or JSON files |
| `ory create workspace` | Create a new Ory Network workspace |

**Key flags for `ory create oauth2-client`**

| Flag | Description |
|------|-------------|
| `--name` | Client name |
| `--grant-type` | Allowed grant types (repeatable) |
| `--response-type` | Allowed response types (repeatable) |
| `--redirect-uri` | Allowed redirect URIs (repeatable) |
| `--scope` | Allowed scopes |
| `--secret` | Client secret (auto-generated if omitted) |
| `--token-endpoint-auth-method` | Authentication method at the token endpoint |
| `--file` | Read client definition from a JSON file |

## ory is

Assert the state of Ory Network resources.

```bash
ory is [command]
```

| Subcommand | Description |
|-----------|-------------|
| `ory is allowed` | Check whether a subject has a permission on an object |

**Key flags for `ory is allowed`**

| Flag | Description |
|------|-------------|
| `--namespace` | Permission namespace |
| `--object` | Object identifier |
| `--relation` | Relation to check |
| `--subject-id` | Subject (user) identifier |

The command exits `0` if the permission is granted and `1` if it is denied.

## ory patch

Patch resources using JSON Patch operations.

```bash
ory patch [command]
```

| Subcommand | Description |
|-----------|-------------|
| `ory patch identity-config` | Patch the Ory Identities service configuration |
| `ory patch oauth2-config` | Patch the Ory OAuth2 and OIDC service configuration |
| `ory patch opl` | Update the Ory Permission Language policy |
| `ory patch permission-config` | Patch the Ory Permissions service configuration |
| `ory patch project` | Patch the project configuration |

**Key flags for `ory patch project`**

| Flag | Description |
|------|-------------|
| `--replace` | Replace a value at a JSON Pointer path: `/path/to/key="value"` |
| `--add` | Add a value at a JSON Pointer path |
| `--remove` | Remove a value at a JSON Pointer path |
| `--file` | Apply patches from a JSON Patch file |

## ory proxy

Run your app and Ory on the same domain using a reverse proxy.

```bash
ory proxy [flags] <upstream-url>
```

<Note>
`ory proxy` is primarily used for local development to route traffic correctly. For most use cases, prefer `ory tunnel`.
</Note>

## ory tunnel

Mirror Ory APIs on your local machine for local development.

```bash
ory tunnel [flags] <upstream-url>
```

The tunnel routes requests through your local machine so that session cookies work correctly across your application and the Ory Network during local development.

```bash
ory tunnel --project $PROJECT_ID http://localhost:3000
```
