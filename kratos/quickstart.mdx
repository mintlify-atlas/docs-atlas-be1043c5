Ory Kratos is a headless identity and user management server. It handles registration, login, account recovery, email verification, and session management through a set of REST APIs — with no bundled UI. This guide walks you through running the official Docker-based quickstart so you can see every flow in action before integrating Kratos into your own application.

<Note>
This guide is a hands-on introduction, not a replacement for studying the full documentation. Understanding [self-service flows](/kratos/self-service) and [identity schemas](/kratos/configuration) will help you use Kratos productively.
</Note>

## Prerequisites

Before you begin, make sure the following tools are installed:

- [Git](https://git-scm.com/)
- [Docker](https://docs.docker.com/get-docker/)
- [Docker Compose](https://docs.docker.com/compose/install/)

Ports `4433`, `4434`, `4455`, and `4436` must be free on your machine. Always use `127.0.0.1` as the hostname — not `localhost` — because browsers treat them as separate domains, which affects cookie behaviour.

<Tip>
Check available disk space before starting: `docker system df`. If volumes are above the 85% threshold, [prune old Docker objects](https://docs.docker.com/config/pruning/) first.
</Tip>

## Run the quickstart

<Steps>

<Step title="Clone the Kratos repository">

Clone the repository and check out the latest release tag:

```shell
git clone https://github.com/ory/kratos.git
cd kratos
```

</Step>

<Step title="Start the Docker Compose stack">

Start all services with the standalone overlay, which includes Kratos, a Node.js self-service UI, and a local SMTP server (MailSlurper):

```shell
docker compose -f quickstart.yml -f quickstart-standalone.yml up --force-recreate
```

If you are on a system with SELinux enabled, add the SELinux overlay instead:

```shell
docker compose -f quickstart.yml -f quickstart-selinux.yml -f quickstart-standalone.yml up --force-recreate
```

Wait until the output shows lines similar to the following — these indicate that Kratos is healthy and listening:

```
kratos_1 | time="..." level=info msg="Starting the admin httpd on: 0.0.0.0:4434"
kratos_1 | time="..." level=info msg="Starting the public httpd on: 0.0.0.0:4433"
```

</Step>

<Step title="Open the application">

Navigate to [http://127.0.0.1:4455/welcome](http://127.0.0.1:4455/welcome). You will see the dashboard of the example application. Because you have no active session, the session information section is empty.

</Step>

</Steps>

## Network architecture

The quickstart runs three services on your host network:

| Service | Port | Purpose |
|---|---|---|
| Ory Kratos public API | `4433` | Handles self-service flows (browser and API) |
| Ory Kratos admin API | `4434` | Admin operations, exposed here for CLI testing only |
| Node.js self-service UI | `4455` | Example application with login, registration, and dashboard |
| MailSlurper (SMTP UI) | `4436` | Catches outgoing emails during development |

The Node.js app communicates with Kratos over Docker's internal network. The browser communicates with both the app and Kratos directly through the host ports.

## Try the self-service flows

### Registration and login

Click **Sign In** from the dashboard to start a login flow. The URL will contain a `flow` query parameter such as `?flow=78e374d2-f36b-40ae-922d-e81f812ea897`. This ID represents the flow object that Kratos created and stored.

Click **Register new account** to start a registration flow. Fill in your email address and choose a strong password. Weak passwords such as `123456` are rejected by Kratos' built-in password policy.

After successful registration you are redirected to the dashboard, where the session information section shows your identity's traits and session metadata.

<Note>
The login form is a standard HTML `<form>`. AJAX requests must include `credentials: 'include'`. Single-page apps using React.js, Angular, or similar frameworks are fully supported.
</Note>

### Inspect a flow with curl

You can inspect the raw flow object that Kratos returns. This is the same data your UI uses to render forms:

<CodeGroup>

```shell login flow
flowId=$(curl -s -X GET \
    -H "Accept: application/json" \
    http://127.0.0.1:4433/self-service/login/api | jq -r '.id')

curl -s -X GET \
    -H "Accept: application/json" \
    "http://127.0.0.1:4433/self-service/login/flows?id=$flowId" | jq
```

```shell registration flow
flowId=$(curl -s -X GET \
    -H "Accept: application/json" \
    http://127.0.0.1:4433/self-service/registration/api | jq -r '.id')

curl -s -X GET \
    -H "Accept: application/json" \
    "http://127.0.0.1:4433/self-service/registration/flows?id=$flowId" | jq
```

</CodeGroup>

The response contains the flow's `ui` object, which lists every form node (fields, labels, submit buttons, CSRF token) needed to render the form.

### Email verification

After registration, Kratos sends a verification email to the address you used. Because the quickstart uses MailSlurper, the email is captured locally rather than delivered to a real inbox. Open [http://127.0.0.1:4436](http://127.0.0.1:4436) to view it.

Click the verification link in the email. You are redirected to the dashboard, and the `verified` field in the session's `verifiable_addresses` array changes to `true`.

To re-request the verification email, go to [http://127.0.0.1:4455/verification](http://127.0.0.1:4455/verification).

### Account recovery

To test account recovery:

<Steps>

<Step title="Initiate recovery">
Log out, then click **Recover Account** on the login screen.
</Step>

<Step title="Enter your email">
Fill in the email address you registered with and submit the form.
</Step>

<Step title="Check MailSlurper">
Open [http://127.0.0.1:4436](http://127.0.0.1:4436) and find the password reset email.
</Step>

<Step title="Set a new password">
Click the link in the email, then enter and confirm your new password.
</Step>

</Steps>

## Quickstart configuration

The quickstart uses a minimal configuration file located at `contrib/quickstart/kratos/email-password/kratos.yml`. The most important settings are:

```yaml title="contrib/quickstart/kratos/email-password/kratos.yml"
version: v0.13.0

dsn: sqlite:///var/lib/sqlite/db.sqlite?_fk=true

serve:
  public:
    base_url: http://127.0.0.1:4433/
    cors:
      enabled: true
  admin:
    base_url: http://kratos:4434/

selfservice:
  default_browser_return_url: http://127.0.0.1:4455/
  allowed_return_urls:
    - http://127.0.0.1:4455

  methods:
    password:
      enabled: true

  flows:
    error:
      ui_url: http://127.0.0.1:4455/error
    settings:
      ui_url: http://127.0.0.1:4455/settings
    recovery:
      enabled: true
      ui_url: http://127.0.0.1:4455/recovery
    verification:
      enabled: true
      ui_url: http://127.0.0.1:4455/verification
    logout:
      after:
        default_browser_return_url: http://127.0.0.1:4455/login
    login:
      ui_url: http://127.0.0.1:4455/login
    registration:
      ui_url: http://127.0.0.1:4455/registration
      after:
        password:
          hooks:
            - hook: session

log:
  level: debug
  format: text
  leak_sensitive_values: true

identity:
  default_schema_id: default
  schemas:
    - id: default
      url: file:///etc/config/kratos/identity.schema.json

courier:
  smtp:
    connection_uri: smtps://test:test@mailslurper:1025/?skip_ssl_verify=true
```

The minimum required settings for any Kratos installation are `identity.default_schema_id` and `dsn`. Configure `selfservice.flows.*.ui_url` for each flow, or Kratos will fall back to its default UI URLs.

## Clean up

To stop all services and remove mounted volumes:

```shell
docker compose -f quickstart.yml down -v
docker compose -f quickstart.yml rm -fsv
```
