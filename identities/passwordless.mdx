---
title: "Passwordless authentication with passkeys and OTP in Ory"
description: "Enable passkeys, WebAuthn, and one-time code login in Ory Identities. Eliminate passwords while keeping authentication secure and phishing-resistant."
---

Passwordless authentication allows users to verify their identity without ever entering a traditional password. Instead of a shared secret, Ory uses cryptographic key pairs (passkeys and WebAuthn) or short-lived codes sent to a trusted channel (email or SMS one-time codes). Removing passwords reduces the attack surface for phishing, credential stuffing, and breached password databases.

Ory Identities supports three passwordless approaches, which you can enable independently or together:

| Method | How it works | Best for |
| :----- | :----------- | :------- |
| **Passkeys** (dedicated strategy) | Public-key cryptography via the WebAuthn API, with browser-native autofill | New projects wanting the best user experience |
| **WebAuthn passwordless** | Public-key cryptography via the WebAuthn API | Projects already using the WebAuthn strategy |
| **One-time codes** | A code sent to the user's email or phone number | Low-friction onboarding; users without biometric hardware |

## Passkeys

Passkeys are the recommended way to implement passwordless authentication in Ory. They use the [FIDO2/WebAuthn standard](https://fidoalliance.org/passkeys/) and are supported by all major platforms and browsers. Unlike the legacy WebAuthn strategy, the dedicated passkey strategy supports **discoverable credentials** and **Conditional UI** — the browser can automatically suggest passkeys via an autofill dropdown on the email field without the user explicitly choosing "sign in with passkey."

Major platform vendors support passkeys out of the box:

- Apple (iCloud Keychain synced passkeys across Apple devices)
- Google (Google Password Manager synced passkeys on Android and Chrome)
- Microsoft (Windows Hello)

Because all implementations follow the same FIDO standard, enabling passkeys in Ory is a single, one-time configuration change.

### How passkey authentication works

<Steps>
  <Step title="Registration">
    When the user registers (or adds a passkey in their account settings), the browser generates a public/private key pair for your application. The **public key** is sent to Ory and stored on the identity. The **private key** never leaves the user's device.
  </Step>
  <Step title="Login challenge">
    At login, Ory sends a cryptographic challenge (a random nonce) to the browser. The browser asks the user to confirm their identity — for example, by using Touch ID, Face ID, or Windows Hello.
  </Step>
  <Step title="Signature verification">
    The authenticator signs the challenge with the private key. The signed response is sent to Ory, which verifies it using the stored public key. No password or shared secret is transmitted.
  </Step>
  <Step title="Session issued">
    Ory creates a session and the user is logged in.
  </Step>
</Steps>

### Enable passkeys

<Tabs>
  <Tab title="Ory Console">
    <Steps>
      <Step title="Open passwordless settings">
        Log in to the [Ory Console](https://console.ory.sh/), select your project, and navigate to **Authentication** > **Passwordless login**.
      </Step>
      <Step title="Enable passkeys">
        Toggle **Enable Passkey authentication** to on.
      </Step>
      <Step title="Set the display name">
        Enter a **Display Name** — this is the label users see when their browser or device prompts them to use a passkey.
      </Step>
      <Step title="Save">
        Click **Save**.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Ory CLI">
    ```bash
    ory patch identity-config --project <your-project-id> \
      --add '/selfservice/methods/passkey/enabled=true' \
      --add '/selfservice/methods/passkey/config/rp/display_name="My App"'
    ```

    For self-hosted Ory Kratos, add the following to your configuration file:

    ```yaml
    selfservice:
      methods:
        passkey:
          enabled: true
          config:
            rp:
              display_name: My App
              # Set to your top-level domain
              id: example.com
              origins:
                - https://auth.example.com
    ```
  </Tab>
</Tabs>

<Note>
If you use a custom identity schema, you must mark the `passkey.display_name` field in the schema to tell Ory which trait to show users during authentication. All Ory preset schemas are passkey-ready by default.
</Note>

### Passkeys vs. WebAuthn strategy

| Capability | WebAuthn passwordless | Passkey strategy |
| :--------- | :-------------------: | :--------------: |
| Discoverable credentials (browser finds passkeys automatically) | No | Yes |
| Conditional UI (autofill dropdown on the email field) | No | Yes |
| Backwards compatibility with WebAuthn strategy users | Yes | No |

Use the passkey strategy for new projects. If you have existing users who registered passkeys with the WebAuthn strategy, you can continue using the WebAuthn strategy or migrate them.

## WebAuthn passwordless (legacy)

The WebAuthn strategy can be configured for passwordless use in addition to its MFA use. It supports the same authenticator types as passkeys (biometrics, USB keys, NFC devices) but does not support Conditional UI or discoverable credentials.

<Note>
For new implementations, use the dedicated passkey strategy instead. The WebAuthn passwordless strategy is documented here for projects that already have users enrolled with it.
</Note>

To enable WebAuthn for passwordless login via the Ory CLI:

```bash
ory patch identity-config <your-project-id> \
  --add '/selfservice/methods/webauthn/enabled=true' \
  --add '/selfservice/methods/webauthn/config/passwordless=true' \
  --add '/selfservice/methods/webauthn/config/rp/display_name="My App"'
```

<Warning>
WebAuthn is limited to one domain. It does not work in native mobile apps. Changing the relying party `id` or `origin` after users have registered credentials will break their ability to log in.
</Warning>

## One-time codes (email and SMS)

One-time code (OTC) authentication is a two-step passwordless flow where Ory sends a short-lived code to the user's registered email address or phone number. The user enters the code to complete authentication. This method requires no special hardware and works for every user who has a valid email or phone number.

### User experience

<Steps>
  <Step title="User enters their identifier">
    The login page shows an email or phone number input. The user enters their email address or phone number.
  </Step>
  <Step title="Code is sent">
    Ory sends a one-time code to the address or phone number. The code is typically valid for a short window (a few minutes).
  </Step>
  <Step title="User enters the code">
    The login page transitions to a code input screen. The user enters the code from their email or SMS.
  </Step>
  <Step title="Session issued">
    Ory verifies the code and creates a session.
  </Step>
</Steps>

### Enable email one-time codes

<Tabs>
  <Tab title="Ory Console">
    In the Ory Console, navigate to **Authentication** > **Passwordless login** and toggle **Enable one-time code passwordless** to on. Click **Save**.
  </Tab>
  <Tab title="Ory CLI">
    ```bash
    ory patch identity-config --project <your-project-id> \
      --add '/selfservice/methods/code/passwordless_enabled=true'
    ```

    Or in a full configuration file:

    ```yaml
    selfservice:
      methods:
        code:
          passwordless_enabled: true
    ```
  </Tab>
</Tabs>

### Enable SMS one-time codes

SMS OTP follows the same configuration steps as email OTP but requires an identity schema with a phone number field and a configured SMS delivery provider.

<Warning>
SMS OTP is considered less secure than email OTP or passkeys due to risks including SIM swapping, SS7 protocol vulnerabilities, and SMS interception. Use it only when stronger options are not available, and consider pairing it with an additional factor.
</Warning>

To enable SMS OTP:

1. Enable the code strategy for passwordless (same as email OTP above).
2. Select an identity schema that includes a phone number field, or add a phone number field to your custom schema:

   ```json
   "phone_number": {
     "type": "string",
     "format": "tel",
     "ory.sh/kratos": {
       "credentials": {
         "code": { "identifier": true, "via": "sms" }
       }
     }
   }
   ```

3. Configure an SMS delivery provider via the Ory CLI or Console.

### Email delivery

For one-time code login to work reliably, you need a properly configured email delivery provider. Ory recommends setting up your own SMTP provider to ensure full control over delivery and branding. You can also customize the email templates for OTP messages.
